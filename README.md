# FineVPS

Каскадный VPN на AmneziaWG с панелью управления. Устройство подключается к серверу 1, российские сайты идут с него напрямую, остальной трафик уходит через сервер 2.

```text
Устройство → AmneziaWG → СЕРВЕР 1 (Россия)
                         ├─ российские сети → напрямую
                         ├─ YouTube → выбранный способ
                         └─ всё остальное ──→ AmneziaWG → СЕРВЕР 2 → интернет
```

## Что нужно

- Два VPS на KVM с внешним IPv4 и доступом root.
- Ubuntu 22.04/24.04/26.04 или Debian 12/13, процессор x86_64.
- На сервере 2 разрешён вход root по паролю. Если он запрещён, установи каскад из терминала: `awg-cascade install`.
- Открытые входящие порты на сервере 1: TCP для панели и UDP для устройств. Сервер 2 должен принимать UDP от сервера 1. Порты выбираются случайно и показываются при установке и в `awg-cascade status`.

## Установка

Подключись к серверу 1 по SSH и выполни:

```bash
curl -fsSL https://raw.githubusercontent.com/morphing888/FineVPS/main/install.sh | sudo bash
```

```text
Команда в терминале
└─ в конце появится одноразовая ссылка на панель
   └─ создай администратора: имя и пароль
      └─ введи IP, порт SSH и пароль root сервера 2
         └─ панель настроит каскад и покажет ход работы
            └─ создай пользователя и подключи устройство
```

Браузер один раз предупредит о сертификате: он создан на сервере 1. Ссылка действует 24 часа, новую покажет `awg-cascade setup-link`.

## Подключение роутера

Роутер подключается так же, как телефон: файлом настроек пользователя или QR-кодом. Нужен роутер с поддержкой AmneziaWG и её параметров `Jc`, `S1`–`S4`, `H1`–`H4`, `I1`, например Keenetic с новой прошивкой или OpenWrt с пакетом amneziawg.

```text
Роутер
├─ отдельный пользователь в панели, например router
│  └─ один пользователь на двух устройствах: они выбивают друг друга
├─ DNS: обычный, например 10.87.1.1 — сервер имён каскада
│  └─ DoT и DoH выключить
├─ «игнорировать DNS провайдера», если такая настройка есть
└─ домашняя сеть выходит в интернет через туннель, а не только сам роутер
```

Почему нельзя DoT и DoH:

- DoT (порт 853) каскад закрывает, иначе запросы обходили бы его сервер имён. С DoT у компьютеров за роутером перестают открываться сайты, хотя туннель подключён.
- DoH идёт мимо сервера имён каскада, поэтому обход YouTube и маршруты по доменам не срабатывают.
- Внутри туннеля DNS и так зашифрован до сервера 1, а дальше каскад отправляет запросы через сервер 2.

Если сайты за роутером не открываются, проверь на компьютере в PowerShell:

```powershell
ping -n 3 1.1.1.1
nslookup ya.ru
```

Если `ping` проходит, а имя не находится, дело в DNS роутера. Если не проходит `ping`, дело в туннеле или в том, что домашняя сеть не выходит через туннель.

## Маршруты

В разделе «Маршруты» для каждого сервиса из каталога выбирается сервер: «Сервер 1», «Сервер 2» или «Как обычно».

```text
Порядок проверки адреса
YouTube (свой раздел) → свои правила → сервисы → российские сети → сервер 2
```

- Сети сервиса берутся из RIPEstat по номеру AS, только если сеть принадлежит самому сервису: Steam, Telegram, Twitch. У Google, WhatsApp, Microsoft и других в общих сетях много чужих сайтов, поэтому для них используются только домены.
- Домены берутся из открытых списков v2fly/domain-list-community, а если список недоступен, из встроенного короткого списка.
- Адреса по доменам собираются из запросов устройств к серверу имён каскада. Поэтому DNS устройств перехватывается, а DNS over TLS (порт 853) закрывается. Если на устройстве включён DNS через HTTPS, правила по доменам для него не сработают.
- При пересечении правил побеждает сервер 2: заблокированное в России через сервер 1 не откроется.
- Списки обновляются раз в сутки вместе с российскими сетями и по кнопке «Обновить списки». Если источник не ответил, остаётся прежний список.

| Команда | Что делает |
|---|---|
| `awg-cascade route list` | показать маршруты сервисов и свои правила |
| `awg-cascade route set steam 1` | Steam через сервер 1. Варианты: `1`, `2`, `auto` |
| `awg-cascade route add example.com 2` | своё правило для сайта, IP-адреса или подсети |
| `awg-cascade route del example.com` | удалить своё правило |
| `awg-cascade route check example.com` | узнать, через какой сервер идёт адрес |

## Обновление

В панели откройте раздел «Обновления» и нажмите «Проверить обновления». Если есть новая версия, появится кнопка «Обновить».

```text
Обновить
└─ скачать выпуск с GitHub → сверить контрольные суммы
   └─ сохранить текущую версию в /etc/awg-cascade/backup
      └─ обновить сервер 1 и программу статистики на сервере 2
         ├─ панель запустилась → готово
         └─ не запустилась → вернуть прежнюю версию
```

На сервере то же делает `awg-cascade update`. Пользователи, адрес и вход в панель, выбранный способ YouTube сохраняются. Повторный запуск команды установки тоже обновляет программу.

Обновление доверяет аккаунту GitHub, из которого выходят выпуски. Включите на нём двухфакторный вход.

## Безопасность

- Ссылка первого входа одноразовая, на диске хранится только её хэш.
- Пароль сервера 2 используется один раз и нигде не сохраняется. Панель создаёт ключ SSH, поэтому дальше сервер 1 входит на сервер 2 по ключу. Это значит, что доступ root к серверу 1 даёт и доступ root к серверу 2. Отозвать ключ можно, удалив строку `awg-cascade` из `/root/.ssh/authorized_keys` на сервере 2.
- Панель открыта только по секретному адресу, пароль администратора хранится в виде хэша, попытки входа ограничены.
- Если забыл пароль панели, на сервере 1 выполни `awg-cascade panel-password`.

## Установка из терминала

Если нужно обойтись без мастера в панели, скачай `awg-cascade.sh` и `awg-cascade-panel` со страницы выпусков и выполни:

```bash
bash /root/awg-cascade.sh install
bash /root/awg-cascade.sh panel-install
```

Первая команда спросит IP сервера 2, порт SSH и имя первого пользователя. Пароль сервера 2 вводится в терминале. Вторая поставит панель и покажет ссылку первого входа.

## YouTube

Режим выбирается в панели, раздел «Серверы», или командой:

| Команда | Что делает |
| --- | --- |
| `awg-cascade youtube exit` | YouTube через сервер 2, режим по умолчанию |
| `awg-cascade youtube direct` | YouTube с сервера 1 без обхода |
| `awg-cascade youtube list` | показать готовые способы обхода |
| `awg-cascade update` | обновить программу с GitHub, при сбое вернуть прежнюю версию |
| `awg-cascade youtube preset p1` | включить способ из списка: `p1`–`p8` zapret2, `p9` приёмы GoodbyeDPI, `t1`–`t3` tpws, `b1`–`b4` ByeDPI, `warp` Cloudflare WARP |
| `awg-cascade youtube-test` | долгий автоподбор, найденный способ появится в списке |

При новой установке YouTube сразу идёт с сервера 1 через tpws, способ `t2` «Разрезание на TLS-записи». Если он не запустится, YouTube пойдёт с сервера 1 без обхода, а способ можно сменить в панели.

GoodbyeDPI работает только на Windows, поэтому на сервере его режим `-9` повторён средствами zapret2. Программы tpws, ByeDPI и wgcf скачиваются при установке панели с проверкой контрольной суммы. tpws и ByeDPI работают как прозрачный прокси только для адресов YouTube. WARP выводит YouTube через отдельный туннель Cloudflare: если он упадёт, YouTube не пойдёт другим путём, пока не будет выбран другой способ.

В режимах с сервера 1 запросы имён устройств попадают на свой сервер имён. Он заносит адреса доменов YouTube в список, и эти адреса идут мимо сервера 2. QUIC к ним отклоняется, поэтому приложения переходят на TCP. Если устройство пользуется своим защищённым DNS, YouTube пойдёт через сервер 2.

## Где что лежит

| Путь | Что там |
| --- | --- |
| `/etc/awg-cascade/` | ключи, параметры, пользователи, список сетей |
| `/etc/awg-cascade/extra-ru.txt` | свои адреса, которые должны идти напрямую (по одному в строке) |
| `/etc/amnezia/amneziawg/` | настройки туннелей `awgclients`, `awguplink`, `awgexit` |
| `/etc/awg-cascade/panel/` | пароль в виде хэша, сертификат и история трафика |
| `/usr/local/sbin/awg-cascade` | сама программа |
| `/usr/local/sbin/awg-cascade-panel` | панель и агент статистики |

## Как устроено

- Правила лежат в отдельных цепочках `AWGC_*`, поэтому не смешиваются с чужими и легко удаляются.
- Трафик самого сервера 1, включая SSH, nginx и 3x-ui, не затрагивается.
- При обрыве связи с сервером 2 зарубежный трафик блокируется и не уходит с российского IP. Российские сайты продолжают работать.
- Список российских сетей обновляется раз в сутки. Если загрузка не удалась или вместо списка пришла посторонняя страница, остаётся прежний список.
- Устройство заворачивает в туннель и IPv6, а сервер его не пересылает. Поэтому IPv6 не обходит каскад, и отключать его на сервере не нужно.

## Как считается трафик

- Панель снимает счётчики раз в 5 секунд и сохраняет историю на диск раз в 5 минут.
- Сервер 1 и сервер 2 на графиках показывают весь внешний трафик, включая служебные данные туннелей.
- «Через сервер 2» считается по туннелю между серверами, «Напрямую» — как разница с туннелем устройств.
- Агент на сервере 2 слушает только адрес внутри туннеля, порт закрыт снаружи фаерволом.
- История: 10 минут по 5 секунд, 2 суток по минутам, 95 дней по часам, суточные итоги за 400 дней.

## Сборка и тесты

`awg-cascade.sh.in` — исходник, `awg-cascade.sh` — готовый файл с подставленным публичным ключом репозитория Amnezia. Панель написана на Go только со стандартной библиотекой, нужен Go 1.24 и новее.

```bash
bash build.sh
(cd panel && go test ./...)
tests/stand.sh
E2E=1 E2E_BIN=/путь/awg-cascade-panel E2E_SHOTS=/путь/к/снимкам tests/stand.sh
```

`tests/stand.sh` запускает сети в пространствах имён Linux и заменяет AmneziaWG обычным WireGuard. Он меняет сетевые настройки машины, поэтому запускать его можно только на тестовой машине.
